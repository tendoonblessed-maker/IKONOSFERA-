# IKONOSFERA — этап 0, PWA-основа

Статус на 28.10.2026: **этап не закрыт**. Это исходный код реального приложения Next.js, а не сервер для переписки. Пользователь пока не может зарегистрироваться и отправить сообщение. Вымышленных сообщений нет.

## Без установки программ на свой компьютер

1. Скачайте архив `IKONOSFERA_stage0_code.zip`, распакуйте его на Windows через «Извлечь всё».
2. Откройте GitHub в браузере и создайте **приватный** репозиторий `ikonosfera` без автоматически созданного README и .gitignore.
3. В репозитории нажмите **Add file → Upload files** и перетащите содержимое распакованной папки с сохранением вложенных каталогов. Если ваш браузер не сохраняет структуру каталогов, не размещайте файлы в одной куче; попросите помощь с импортом или воспользуйтесь GitHub Desktop позже. Файлы `.env.local` и секреты не загружайте.
4. В интерфейсе GitHub подтвердите загрузку в `main`. Затем создайте ветку `dev` через меню веток: введите `dev` и выберите **Create branch: dev from main**.
5. В Vercel откройте **Add New → Project**, выберите GitHub и репозиторий `ikonosfera`. Root Directory: `/`, Framework: Next.js, Production Branch: `main`. **Не добавляйте секреты** на этом этапе.
6. Нажмите Deploy. Сборка скачивает pinned npm зависимости из `package.json`; требуется доступ Vercel к npm и Google Fonts на этапе сборки. При ошибке отправьте полный Build Log.
7. После успешной сборки перейдите по HTTPS-адресу вида `https://<name>.vercel.app`. Фактический адрес выдают Vercel, в этом архиве его нет.
8. На iPhone откройте именно Production HTTPS URL в Safari. Нажмите «Поделиться → На экран Домой → Добавить». Откройте иконку с рабочего стола и проверьте **обе версии**: Safari и PWA. Также проверьте сайт в браузере на Windows.

> Важно: публичная демо-версия без авторизации и БД не предназначена для настоящих переписок или реальных персональных данных. Наличие HTTPS не делает продукт юридически готовым к запуску.
>
> Примечание по доступу с iPhone: некоторые Vercel Preview Deployment защищены логином Vercel. Для первой проверки используйте Production URL на неперсональных тестовых данных. Не выключайте защиту приватных preview ради удобства.

## Если нужна просто визуальная проверка без сервера

Откройте двойным щелчком `prototype/IKONOSFERA_stage0_preview.html`. Это автономный визуальный просмотр оформления, **не** настоящее приложение Next.js или PWA, и не содержит реальных сообщений. Старое принятая концепция сферы сохранена в `prototype/IKONOSFERA_demo.html` до этапа 7.

## Для разработчика (Windows PowerShell)

```powershell
# В распакованной папке, где находится package.json
npm.cmd install --no-audit --no-fund
npm.cmd run dev
# Открыть http://localhost:3000
```

Для проверок:

```powershell
npm.cmd run typecheck
npm.cmd run lint
npm.cmd test
npm.cmd run build
```

После первого успешного `npm install` сохраните созданный `package-lock.json` в Git. После этого в GitHub Actions можно заменить `npm install` на `npm ci` для воспроизводимых сборок. CI уже проверяет типы, базовые правила и тесты. Серьёзный линтер ESLint **пока не подключён**: это новая зависимость, потребуется согласование.

## Что реально реализовано

- Next.js App Router, TypeScript, Tailwind v3 с `tailwind.config.ts`, дизайн-токены.
- Пустая переписка без подмены реальных сообщений; отправка выключена.
- Переключение RU/EN через внутренние словари. Отдельная i18n-библиотека пока не добавлялась, требуется согласование.
- PWA manifest, иконки any/maskable и Apple Touch Icon, ручной Service Worker для офлайн-экрана.
- Подсказка Safari «Поделиться → На экран Домой» один раз; условная установка в Chrome/Edge через браузерное событие.
- `prefers-reduced-motion`, OLED-чёрный фон, safe area, 16px основной текст, контрастные цвета, клавиатурные кнопки.
- GitHub Actions для проверки (после создания GitHub-репозитория).

## Что не реализовано

- Нет GitHub-репозитория у пользователя, веток, коммитов, тегов, реального Vercel deployment.
- Нет Supabase dev/prod, PostgreSQL, RLS, миграций, SMTP, Sentry, домена, авторизации, Realtime или переписки.
- Нельзя использовать демо для тестирования двух реальных пользователей.
- Из-за недоступного npm registry здесь не запускались `npm install`, полноценный TypeScript typecheck и Next.js build. Проведены отдельные статические проверки и Node-тесты.

## Откат и защита данных

Когда Git будет настроен и этап 0 закрыт после проверки, разрешённые команды:

```powershell
git add .
git commit -m "feat: stage 0 verified PWA foundation"
git tag stage-0-ok
git push origin main
git push origin stage-0-ok
```

Для просмотра прежней рабочей версии: `git switch --detach stage-0-ok` (не редактируйте отсоединённый HEAD). Для возврата к `main`: `git switch main`. Перед сбросом рабочей ветки сохраните локальные изменения; разрушительные `reset --hard` и `push --force` без согласования не используем.

При наличии Vercel Deployment откат через Vercel Dashboard → Project → Deployments → предыдущий успешный Production Deployment → **Redeploy/Promote to Production**, в зависимости от доступных действий и текущего UI. После отката проверьте домен и версию; никакой откат кода сам по себе не отменяет миграции БД. На этапе 0 миграций нет. В будущем перед миграцией production делать резервную копию и писать отдельную обратную миграцию после оценки влияния на данные.

## Вопросы перед работой с реальными данными

Для пользователей из РФ требуется юридическая оценка первичной локализации персональных данных и соответствующего региона/хостинга. До решения нельзя подключать реальную пользовательскую БД в зарубежный проект и приглашать пользователей с настоящими данными.
