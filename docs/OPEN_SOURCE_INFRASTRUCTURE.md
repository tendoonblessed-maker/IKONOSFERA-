# Открытая инфраструктура: что подходит IKONOSFERA

Проверено 29 октября 2026 года. Это **матрица совместимости**, а не разрешение
переносить исходники чужих клиентов без соблюдения лицензий и авторства.

## Источники и ограничения

| Проект | Код и лицензирование | Что изучать | Решение для IKONOSFERA |
| --- | --- | --- | --- |
| Telegram Desktop | [telegramdesktop/tdesktop](https://github.com/telegramdesktop/tdesktop), GPL-3.0 | Навигация, черновики, история, кеширование, поведение списка чатов | Опираться на пользовательские сценарии; **не переносить GPL-код** в веб-клиент без отдельного решения о лицензировании всего приложения |
| Telegram Android / iOS / Web | [telegram.org/apps](https://telegram.org/apps): Android/iOS GPL-2.0+, Web/desktop GPL-3.0 | Подходы к истории, уведомлениям, медиа, состоянию чатов | Отдельно реализовывать на React/TypeScript и Supabase |
| Telegram TDLib | [tdlib/td](https://github.com/tdlib/td), Boost 1.0 | Модель очереди сообщений, синхронизация и состояние клиента | TDLib является **клиентом Telegram**, а не готовой серверной инфраструктурой IKONOSFERA; без Telegram API/MTProto не подключается |
| Swiftgram iOS | [Swiftgram/Telegram-iOS](https://github.com/Swiftgram/Telegram-iOS), форк Telegram iOS | UX быстрых действий, интерфейс и управление несколькими переписками | Не переносить части Swift/GPL в Next.js |
| Swiftgram TDLibKit | [Swiftgram/TDLibKit](https://github.com/Swiftgram/TDLibKit), MIT | Native Swift wrapper и архитектура абстракций | Пригодится только при создании **отдельного нативного Telegram-клиента**; в текущий Supabase-мессенджер не подключать |
| Nicegram Android/iOS/desktop | [nicegram](https://github.com/nicegram), Android GPL-2.0, другие клиенты — Telegram-форки | Управление каналами и аккаунтами, удобство действий, приватность | Изучать сценарии, не копировать реализацию и брендинг |
| Nicegram WebRTC | [nicegram/webrtc](https://github.com/nicegram/webrtc), BSD-3-Clause | Сеть, аудио/видео, вызовы | Только для нативного проекта; для веба лучше браузерный WebRTC + собственная сигнализация |
| Неофициальные библиотеки WhatsApp | [wwebjs/whatsapp-web.js](https://github.com/wwebjs/whatsapp-web.js) (Apache-2.0), [WhiskeySockets/Baileys](https://github.com/WhiskeySockets/Baileys) | Модель доставки и очередей, тестирование событий | **Не являются исходным кодом WhatsApp** и используют его сервис, а не собственный сервер; не интегрировать в IKONOSFERA без отдельной задачи на совместимость и проверки условий платформы |

Важно: у официального WhatsApp нет доступного для переноса полнофункционального
открытого исходного кода клиентского приложения или сервера. Публикации
неофициальных библиотек не делают WhatsApp открытым проектом.

Для внешнего кода всегда проверять лицензию **конкретного файла, версии и
зависимостей**; MIT/Apache/BSD не отменяют требований о сохранении уведомлений
об авторстве и лицензии. Для каждого будущего заимствования нужен отдельный
license-review и тесты. Иконки, торговые марки и оформление конкурентов не
копировать.

## Что интегрировано сейчас

- **Приватные черновики групп**: `lib/group-drafts.ts`, отдельный ключ на
  пользователя и отдельный индекс на группу, только `sessionStorage` вкладки.
  Содержимое черновика не отправляется в Supabase.
- **Непрочитанные черновики на главной**: пометка «Черновик» и текст в строке
  группы, без изменения данных серверного last-message.
- **Удобный ввод**: многострочный редактор, Enter/Shift+Enter на ПК,
  предотвращение мобильного увеличения страницы при фокусе, защита текста
  от ошибок отправки/переключений, отсутствие автоповтора при восстановлении
  соединения.
- **Реальный REST + Realtime**: уже внедрённая инфраструктура Next.js,
  Postgres RLS, Supabase Auth, Storage, авторизованные события и HTTPS fallback.
  Новые внешние GPL/Telegram/WhatsApp зависимости в данном изменении **не добавлены**.

Эти функции реализованы **самостоятельно**, по требованиям IKONOSFERA. Чужой
фрагмент исходного кода из Telegram, Nicegram, Swiftgram или WhatsApp не
встраивался.

## Приоритетная дорожная карта для стабильного мессенджера

1. **Безопасность**: аудит SQL `SECURITY DEFINER`, ограничение анонимных
   регистраций, CSP, меры против XSS, антиспам и жалобы.
2. **Надёжность доставки**: клиентский UUID и серверная дедупликация
   `group_messages.id` для безопасного *ручного* повтора теперь внедрены.
   Следующая задача — отдельная очередь с явным подтверждением, доставкой
   при закрытой вкладке и аккуратной синхронизацией статусов. Автоматически
   повторять POST без проверки подтверждения всё равно нельзя.
3. **Уведомления**: web push по согласию пользователя, серверный VAPID и
   защита от утечек содержимого в уведомлениях.
4. **Медиа**: отдельная очередь загрузок, возобновление прерванных больших
   файлов и безопасные предварительные просмотры.
5. **Масштабирование**: приватные темы Supabase Broadcast с проверкой прав,
   вместо широких подписок на Postgres Changes, нагрузочные тесты и метрики.
6. **Звонки**: браузерный WebRTC со своими STUN/TURN и сервером сигнализации;
   отдельная модель разрешений и приватности.
7. **Шифрование**: только исследованная схема E2EE со стандартизованными
   протоколами, проверкой устройств, управлением ключами и восстановлением;
   нельзя «скопировать шифрование Telegram» и считать готовым.

Этот файл — **технический план**, а не утверждение, что перечисленные в
дорожной карте функции уже работают.
