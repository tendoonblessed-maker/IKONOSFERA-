# IKONOSFERA — подключение переписки 1:1 (подготовлено, не запущено)

## Текущий статус

Подготовлены React-интерфейс, **собственный минимальный REST-клиент** `lib/supabase-rest.ts`, SQL-схема и RLS. Сторонние пакеты не добавлены. Клиент использует Supabase Auth **email OTP**, PostgREST и обновляет сообщения каждые **3 секунды** (это не WebSocket и не мгновенная гарантия доставки).

**На 28.10.2026 нет подключённой базы, подтверждённой юрисдикции для хранения персональных данных граждан РФ, настроенных почтовых отправлений и пройденных RLS-тестов. Переписка с реальными пользователями пока недоступна.**

## Перед включением

1. Выбрать законную схему первичной обработки и хранения персональных данных граждан РФ. Для тестового Supabase за рубежом — только искусственные данные, без реальных пользователей из РФ.
2. Создать отдельный dev-проект Supabase в выбранной организации; проверить тариф и регион **до** создания. Production отделить.
3. Проверить и однократно применить `supabase/migrations/20261028_120000_direct_messages.sql` в подходящей базе. Не запускать миграцию повторно после частичного сбоя без разбора.
4. В Supabase Auth включить Email OTP и подтвердить, что реально приходит **числовой код**, а не только magic link. Настроить разрешённый адрес сайта `https://ikonosfera.vercel.app`, SMTP и лимиты отправки до приглашения пользователей.
5. В Vercel Environment Variables добавить только публичные `NEXT_PUBLIC_SUPABASE_URL` и `NEXT_PUBLIC_SUPABASE_ANON_KEY`, **не service_role**. Значения не вставлять в GitHub и переписку. Пересобрать проект: переменные NEXT_PUBLIC встраиваются во время сборки.
6. Пройти проверки `supabase/tests/README.md` от имён разных реальных test-JWT (A, B, C). Проверки от роли postgres или service_role **не считаются** проверкой RLS.
7. На iPhone Safari и установленном PWA, Android Chrome и установленном PWA, Windows Chrome/Edge: войти, задать username, открыть `/u/username`, создать чат, отправить сообщения в обе стороны, обновить страницу и проверить сохранение.

## Возможности подготовленного UI

- Пустой список настоящих чатов, поиск среди уже созданных чатов, контакты и настройки.
- Регистрация и вход по шестизначному коду на email; профили с уникальным `username` и `display_name`.
- Создание личного диалога по username и публичная ссылка `/u/[username]` (ссылка **не** раскрывает историю сообщений).
- Чтение/отправка текстовых сообщений, сохранение в Postgres; обновление данных примерно раз в 3 секунды. Пока **нет** Realtime-подписки, push, медиа, звонков, групп, E2EE, блокировок и антиспама.
- HTTPS + manifest + service worker (без кэширования приватных сообщений). Установка через Chrome Android и Safari iPhone.

## Ошибки

- «Сервер не подключён» — NEXT_PUBLIC-переменные не заданы в сборке.
- `permission denied` — проверить grants, RLS и JWT, **не отключать RLS**.
- Ошибка Email/OTP — проверить настройки Auth, шаблон OTP, SMTP, лимиты и подтверждение email.
- Не видны чужие сообщения — проверить членство, корректность JWT, регулярное обновление, не подставлять чужой sender_id.

## Откат

- Ветку `work/messenger-mvp` можно удалить или оставить, `main` и текущая публикация Vercel не меняются до проверки.

- Если миграция когда-нибудь применена, откат данных требует отдельной проверенной обратной миграции и резервной копии; Git revert БД не откатывает.
