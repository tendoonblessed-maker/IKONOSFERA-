# Прочтение личных сообщений — 29.10.2026

Раньше каждый успешный GET последних сообщений безусловно отправлял
`mark_chat_messages_read`, даже в фоне или при чтении старой истории.
Теперь запрос делается лишь после отображения новых сообщений в React,
в видимой вкладке, при скролле к последним сообщениям.

В истории новые входящие сообщения (кроме своих, скрытых и ранее показанных)
показываются счётчиком на кнопке прокрутки вниз (до 99+).
Состояние сбрасывается при переключении чата и пользователя.
При неудачном RPC допускается повтор на следующем обновлении/прокрутке.

Нет миграций БД или изменения RLS. Осталось небольшое серверное окно гонки:
существующий RPC подтверждает *все* непрочитанные, а не «до видимого ID».
Для строгой гарантии потребуется отдельный ограниченный по ID серверный RPC,
предварительно испытанный на staging, без изменения production сейчас.

Проверить `node --test tests/direct-read-position.test.mjs`, `npm run check`,
а также вручную на iOS Safari и Windows Chrome: старую историю, фоновую вкладку,
счётчик, переход вниз, переключение аккаунта и восстановление сети.
